# Development log — what was tried, what broke, what the final code does

The code here is the code that produced the reference results (verified: this restructured package reproduces the earlier pipeline's output **pixel-identically** on seeds 0–5). Below are the iterations that got each step to its working state.

## Step 1 — entity graph
- `num2words` has no Hindi → wrote `hindi_numbers.py` (0–99 table, Indian grouping: हज़ार/लाख/करोड़) so amounts exist as digits **and** correct words.
- Boundary/area clauses produced "0 बीघा" → areas now `randint(1, 9)`.

## Step 2 — text
- Clauses came out in odd order → optional clauses are slot-based (slot 0 before price, slot 2 after rights) so the legal flow stays natural.
- Gemini writer built against a fake client first: JSON output, verbatim fact check, retry that names the missing facts, 429 backoff honouring "retry in Ns", disk cache (`tests/test_gemini_writer.py`). Never run against the real API yet.

## Step 3 — layout
- Original problem: text filled half the page. Fix: fix the page size first, then **fit** the font (binary search) and then stretch line-height/gaps until fill is 90–96.5 %; text is rewritten longer/shorter if the fit overflows/underfills.
- Header text spread out by flexbox → each side wrapped in a `<span>`.
- Word boxes verified by drawing them over the render (no off-page words).

## Step 4 — compose
- Paper looked blotchy → colour desaturated to 0.55.
- Marks/signatures kept faint specks in their crops → mass-trim cropping (`crop_to_alpha`).
- `place()` ignored height-only sizing → fixed.
- Stamps 1–4 contain "2023" dates / English "SAMPLE" → `skip_assets` option (decision pending).
- Overlay text, stamps, marks, notes are unscored; transcript order verified.

## Step 5 — degradation
- First run crashed: `__import__("PIL.ImageDraw")` returned the module, not the class → proper import.
- First torn edge copied the 2-D mask from the photo and tiled it → blobby black "feet" on top/bottom edges. Rewritten to use only the photo's 1-D contour (scaled, mirrored-tiled, plus fine noise); looks natural on all four sides.
- Augraphy uses global RNGs → pages were not reproducible. Now seeded per call and state restored.
- Augraphy `BadPhotoCopy` sometimes dies inside numba (seed 20) → wrapper fails soft and logs `augraphy.<Op>.FAILED` in the ops list.
- Polygon tracking checked by drawing the transformed word boxes on the damaged pages (rotation, perspective, bend, tear).

## Step 6 — export
- First batch run: 4 Chromium workers on a 2-core box timed out → default 2 workers, background run, resumable (label JSON = done marker).
- Labels originally lacked the entity facts needed for fact recall → added `facts`.

## Step 7 — evaluation
- Srinidhi's `normalize()` strips Devanagari vowel signs and virama → own normaliser.
- rapidfuzz: passing opcodes through `Opcodes()` raised "List of edit operations invalid" → use `Levenshtein.opcodes` directly.
- GeminiOCR tested against a stub client (rate-limit retry, cache hit).

## Step 7 — verification (added after the user asked to focus on verifiable generation)
- Built independent checks (facts, amount words parsed back to a number, label/text consistency, layout, composition, damage, polygons) and a pixel alignment check.
- Alignment check v1 was too weak: a deliberately shifted control still passed 40–77 %. v2 measures in each word's own frame (ink must reach both box ends, sit mid-box); control collapsed to ≈0 %.
- Real pages then failed 30–45 % of words. Cause 1 (verifier): the vertical-centre test assumed one font metric; fonts differ → replaced with "middle 60 %". Cause 2 (**real bug in the ground truth**): word boxes came from the DOM content area, which is far taller than the ink for fonts like Gargi/Sarai and overlapped neighbouring footer lines. Fixed: boxes now use `canvas.measureText` ink ascent/descent per word (tight to ±4 px of the ink); lines are still grouped by the stable DOM top. Images are unchanged; only label boxes got tighter.
- First attempt at the fix used `getComputedStyle().font`, which silently fell back to a default 10px font in the page (boxes too short); fixed by building the font string from longhands.
- Final-image check is lenient (≥60 %): very faint/blurred pages lose ink pixels (false alarm seen once, boxes were correct).
- `text_stamp` is a procedural stamp, not an asset file — whitelisted in `composition_valid`.
- Added 6 Devanagari fonts (Gargi, Lohit, Sarai, Nakula, Kalimati, Samanata) after a render comparison; rejected Sahadeva (glyph error in आ), Chandas (odd ५), FreeSerif (odd numerals). Old 3-font config kept as `hindi_sale_deed_v1_reference.yaml`.
- Result: 24/24 pages pass; 3/3 regenerated byte-identical.

## Packaging (this refactor)
- One file per step, `orchestrator.py` saves every step's output, `main.py` CLI. Regression: new package vs old on 6 pages = identical pixels; `--from-step 5` reproduces byte-identically; smoke test in `tests/`.

## v2 extension, part 1 (fonts, sizes, handwriting) — Checkpoint 1
Goal: more variety (fonts, sizes, handwriting) with **nothing changing for the existing configs**. Everything new lives in `config/hindi_sale_deed_v2.yaml` and is switched on only by keys that the old configs do not have (`note_font_files`, `size_plan`, `page_style`, `handwriting`, and `files:` on a font entry).
- **Regression gate first** (`tests/regression_gate.py`): 17 pages (every page size, all 9 + 3 fonts, both alignments) through steps 1-6 incl. the dataset export; every output file is hashed, labels included. Tier A uses fixed Chromium flags so pixels are comparable; Tier B uses production flags (JSON exact, image sizes). It passed unchanged after every phase. The golden hashes belong to the machine that recorded them: re-record with `--record` from an unmodified checkout on a new machine.
- **Fonts**: 27 Google Fonts files in `assets/fonts` (OFL). Loaded with `@font-face`, not installed. Glyph-coverage test + rendered preview. Rejected after the preview: Dekko, Kurale (broken conjuncts), Sarala (ड़ drawn like ङ). Each page records whether its font file really loaded; verify fails the page if not.
- **Sizes**: `size_plan` picks a target body size per page (own random stream); the writer is asked for the matching amount of text and the fitter fills the page at about that size (17-32 px seen).
- **Handwriting**: `page_style` = printed / hybrid / handwritten. Hybrid writes names, dates, amounts and any digit-bearing word by hand (matched from the entity graph); handwritten pages use Kalam or Amita, left aligned. Per-word jitter only (rotation, baseline shift, size, ink strength): per-letter jitter would break Devanagari shaping. Each hand word has a 4-point polygon computed from the transform that was really applied, and its horizontal extent comes from `measureText` ink bounds (script fonts overhang).
- **Verify**: new `font_file_loaded` check; polygon overlap check for tilted words; ink threshold for v2 pages taken from the body text itself (a faint thin font under a dark stamp was a false alarm, boxes were right); vertical-centre band widened for hand words. Real-vs-shifted-control separation stays large (0.94+ vs <=0.39 on hand pages, ~0.01 on average).
- **Labels**: v2 only. Words get `"hand": true`; the label gets a `style` block. v1 labels are byte-identical (gate).
- **Known, not changed**: Augraphy `BadPhotoCopy` is not reproducible (its numba code has an unseeded RNG), so pages whose recipe contains it differ in the last image on every run. This contradicts the byte-identical claim in the README for those pages. Fixing it would change existing output, so it is left as is; the gate compares everything else on such pages exactly.

## v2 extension, part 2 (staged degradation) — Checkpoint 2
- `degrade.staged` in the v2 config switches on `degrade_page_staged` (step 5, new function; the old `degrade_page` is untouched). Stages: 1 scan wear, 2 paper ageing, 3 ink damage, 4 geometry and physical, 5 severe. Strength per stage 0.45 / 0.7 / 1.0 / 1.3 / 1.7 (old light / medium / heavy were 0.6 / 1.0 / 1.5). Folds, torn edge, rotation, noise and JPEG are always on and scale with the stage; the other damages appear from their group's stage on, with a chance that climbs to its stage-5 value.
- **Nesting**: every damage has its own random stream (page seed + damage name), so the recipe does not depend on the stage. One uniform draw per damage is compared with a ramp that only rises, so a damage present at stage k is present at k+1. Stage k+1 = stage k plus more, at higher strength.
- One image per page by default, the stage drawn from `stage_weights` (provisional 0.10/0.15/0.25/0.30/0.20). **Ladder** (`degrade.staged.ladder`, off by default, listed splits only): five images per page, `doc_X_s1..s5`, same layout, same recipe, same split (shared seed). The base image of a ladder page is not exported, to avoid a near-duplicate.
- Each staged page measures its own difficulty from pixels: body-text contrast and sharpness relative to the clean target, and the share of covered or cut-off words (`measure` in the record and label). Guardrails (`degrade.guardrails`) only measure and log what they would reject (`provisional`, `enforced: false`); enforcement and real limits come with the calibration.
- Verify: ladder pages run all page checks per stage plus a monotonic check **on the measurements**, with tolerances for random page detail (coverage 0.03, contrast and sharpness ratio 0.10), and stage 5 must be measurably harder than stage 1. The first tolerances (0.06) failed 2 of 8 ladder pages by 0.06-0.07 on contrast (lighting noise), so contrast was widened.
- Severity field: staged pages map stage 1-2 to light, 3 to medium, 4-5 to heavy so existing reports keep working.

## v2 extension, part 2b (feedback after Checkpoint 2): more handwriting, larger type
- **Larger type**: size bands now reach 48 px (`size_plan.fs`, last band 34-48, 25 % of pages). The full template deed has about 215 words at minimum, which cannot be set above about 32 px on one page, so target sizes from `compact_above` (34) use a **short-form deed** (`write_compact`, about 90 words, same facts, fewer clauses). Seen: 40-48 px. v1 writer untouched. Header, footer, stamps and notes are capped at 30 px so only the body grows.
- **Handwriting**: share raised to 35 % (printed 35, hybrid 30). More natural: per-line baseline wobble and tilt, per-word slant (skew), uneven word gaps, a per-page "messiness" factor (0.7-1.9) that scales all jitter, and a soft ink-bleed glow. Polygons include skew.
- Verify for hand words: the vertical window around a word is 0.1 box heights (was 0.3) so tilted neighbouring lines do not leak in; this widens nothing but the control rate on hand pages is higher (up to about 0.5 against 0.98+ for real alignment).
- Ladder: sharpness tolerance grows with the value (a ratio of small numbers on blurred pages jumped 0.2 to 0.3 on one page).

## v2 extension, part 3 (difficulty label and calibration) — final
- `pipeline/difficulty.py`: score 0..1 from seven components (stage, lost contrast, lost sharpness, covered words, handwriting share, small text, font) with weights and thresholds in the config. Written into v2 labels (`difficulty`, with the components). Provisional weights and thresholds (0.22 / 0.46 gave 25 / 40 / 35 % easy / medium / hard on 60 default-sampled pages) until calibrated.
- `tools/calibrate.py` (models, make-set, run, spotcheck, analyze) and `python main.py models`. Stores raw per-image error rates, the OCR model name, the prompt text and its hash, and a clean-image baseline per style (OCR of the aligned clean target). Analysis uses excess CER over that baseline, checks error rises with stage per style, fits weights by non-negative least squares (blended with the provisional weights below 300 images), derives 20 / 40 / 40 thresholds and stage weights, and turns the human readable / not readable answers into guardrail limits. Steps in `docs/CALIBRATION.md`.
- Guardrail enforcement (`degrade.guardrails.enforce`): a page past a limit is redone one stage lower until it passes or reaches stage 1; the record notes `downgraded_from`. Ladder variants are never enforced.
- Tested: the whole chain offline with the fake OCR (not a calibration), synthetic-data analysis test, stub-client model listing, forced enforcement. **Not tested: the real Gemini calls** (the API is not reachable from the build environment); they use the same `GeminiOCR` class as the older `evaluate` command.
